# SQL Frameworks - File Storage -> Compute Storage

## Ponteiros que guardam TB

- **BigInt**: 8 bytes, -9e18 a 9e18, ponteiro para exabytes
- **Int**: 4 bytes, até 2B, use para chunk_index
- **String/Text**: path ou storage_key s3://bucket/uuid
- **Json/JsonB**: manifesto, não container (base64 +33% anti-pattern)
- **Bytes/Bytea/Blob**: chunk 1MB seguro
- **Postgres**: varlena limite 1GB por campo TOAST, table 32TB, database unlimited, pg_largeobject 4TB por OID
- **MySQL**: LONGBLOB 4GB (2^32-1), row 65K exceto blob off-page

## Pattern chunking TB

```sql
CREATE TABLE files (id BIGSERIAL PRIMARY KEY, size_bytes BIGINT, storage_key TEXT, hash TEXT, metadata JSONB);
CREATE TABLE file_chunks (file_id BIGINT REFERENCES files(id), chunk_index INT, data BYTEA, PRIMARY KEY(file_id, chunk_index)) PARTITION BY HASH(file_id);
```

## 10 Frameworks

1. **Prisma**: Bytes->bytea PG, LONGBLOB MySQL, BLOB SQLite, Json->jsonb
2. **Drizzle ORM**: customType para bytea, leve, type-safe
3. **TypeORM**: @Column type: 'bytea' / 'longblob'
4. **Sequelize**: DataTypes.BLOB('long')
5. **Knex**: table.binary('data')
6. **Better SQLite3**: nativo rápido, sync, ideal para turso local
7. **mysql2**: driver rápido, suporte LONGBLOB
8. **pg**: driver PG nativo, suporte bytea + large object
9. **MikroORM**: suporte para todos, DataLoader
10. **TypeDORM**: DynamoDB ORM, mas pattern similar

Todos transformam file storage em compute: baixa chunk de S3/R2, monta em /mnt/ramdisk (tmpfs), executa.
