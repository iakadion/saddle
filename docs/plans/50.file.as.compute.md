# V6 - File Storage como Compute Runner via Tabelas do Site

## Ideia

Publica site próprio com Prisma Schema, e começa a gravar tudo na tabela do site. File storage limitado (500MB GitHub) distribuído em N repos, transformado em runner de computação.

## Como

1. Site = 1 tabela Site com Json data + relação File + FileChunk
2. File = manifesto com storageKey pointer para S3/R2/HF/Kaggle/Terabox/NPM CDN + size BigInt + chunks
3. FileChunk = 1MB por linha, seguro em qualquer provider, reconstrói binário em /mnt/ramdisk
4. ComputeJob = fila de jobs, status queued/running/done, runner github/forgejo/codeberg

## Fluxo file storage -> compute runner

- Browser arrasta binary.wasm (600MB)
- Site fatia em 600 chunks 1MB, insere em FileChunk via Prisma (distribui em 10 repos workers, cada 60 chunks)
- Cria ComputeJob status queued
- Action worker (terceiro) faz SELECT chunks WHERE fileId, reconstrói em /mnt/ramdisk (tmpfs 8GB), executa via WASI/Node, salva resultado em FileChunk result ou storageKey R2
- UPDATE ComputeJob status done, resultUrl = CDN jsDelivr do resultado
- Browser polling GET /api/jobs/:id, baixa resultado via CDN

## Ponteiros TB

- BigInt id: 9 quintilhões arquivos
- BigInt size: >2GB
- String storageKey: s3://bucket/uuid ou blob_id
- Json metadata: exif, signed url
- Bytes data: só <10MB, resto chunking

## 10 CDNs como compute

jsDelivr, UNPKG, esm.sh, cdnjs, Statically, GCore, R2, B2, Supabase Storage, HF Hub CDN - todos free egress, servem chunks como CDN ilimitado.
