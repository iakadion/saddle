# Saddle Deploy Strategy

> Deploy strategies for the saddle robot across Netlify, Vercel,
> GitHub Actions, GitLab CI, Forgejo, and self-hosted infrastructure.

## Overview

Saddle robot supports multiple deployment strategies to make the bot
available across platforms. Each strategy uses HTTPS communication
between deployed sites for coordination and data transfer.

## Strategy 1: Netlify

Netlify provides serverless functions and static hosting for the
saddle robot web interface.

### Configuration

```toml
# netlify.toml
[build]
  publish = "dist"
  command = "npm run build"

[[redirects]]
  from = "/api/*"
  to = "/.netlify/functions/:splat"
  status = 200

[[headers]]
  for = "/*"
  [headers.values]
    X-Frame-Options = "DENY"
    X-Content-Type-Options = "nosniff"
```

### Environment Variables

| Variable | Description | Required |
|----------|-------------|----------|
| `SBOT_TOKEN` | GitHub/GitLab bot token | Yes |
| `SBOT_PLATFORM` | Target platform (github, gitlab, forgejo, gitea) | Yes |
| `SBOT_MEMORY_BUCKET` | Storage bucket for memory persistence | Yes |
| `SBOT_WEBHOOK_SECRET` | Webhook signature secret | Yes |
| `SBOT_CDN_URL` | SCDN endpoint for static assets | No |

### Deploy Command

```bash
# Deploy to Netlify
netlify deploy --prod
# Deploy to Netlify staging
netlify deploy --context deploy-preview
```

## Strategy 2: Vercel

Vercel provides edge functions and instant deployment for the
saddle robot backend.

### Configuration

```json
// vercel.json
{
  "version": 2,
  "builds": [
    {
      "src": "web/index.js",
      "use": "@vercel/node"
    },
    {
      "src": "web/api/*.js",
      "use": "@vercel/node"
    }
  ],
  "routes": [
    {
      "src": "/api/(.*)",
      "dest": "/web/api/$1"
    }
  ]
}
```

### Environment Variables

Same as Netlify strategy. Add Vercel-specific:

| Variable | Description |
|----------|-------------|
| `VERCEL_REGION` | Edge region for deployment |
| `SBOT_MEMORY_ENGINE` | Memory engine type (ram, storage, bucket) |

## Strategy 3: GitHub Actions Pipeline

Use GitHub Actions to deploy and run the saddle robot as a
scheduled or triggered workflow.

### Workflow File

```yaml
# .github/workflows/saddle-robot.yml
name: Saddle Robot Automation

on:
  schedule:
    - cron: '*/15 * * * *'
  workflow_dispatch:
  push:
    paths:
      - 'saddle-robot/**'
      - '.saddle/config.yml'

permissions:
  contents: read
  pull-requests: write
  issues: write
  actions: write

env:
  SBOT_PLATFORM: github
  SBOT_MEMORY_BUCKET: ${{ secrets.MEMORY_BUCKET }}
  SBOT_WEBHOOK_SECRET: ${{ secrets.WEBHOOK_SECRET }}

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci --production

      - name: Run saddle robot
        run: node saddle-robot/index.js
        env:
          SBOT_API_TOKEN: ${{ secrets.SBOT_TOKEN }}
          SBOT_MEMORY_ENGINE: storage

      - name: Upload memory artifacts
        uses: actions/upload-artifact@v4
        with:
          name: memory-logs
          path: |
            .saddle/logs/*.json
          retention-days: 30

  deploy-to-netlify:
    needs: [deploy]
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: jsmrcaga/action-netlify-deploy@v2.5.1
        with:
          netlify_auth_token: ${{ secrets.NETLIFY_TOKEN }}
          netlify_site_id: ${{ secrets.NETLIFY_SITE_ID }}
          deploy_message: 'Saddle robot auto-deploy'
```

### GitHub App Configuration

Create a GitHub App for the saddle robot with these permissions:

| Permission | Access |
|------------|--------|
| Contents | Read/Write |
| Pull Requests | Read/Write |
| Issues | Read/Write |
| Actions | Read/Write |
| Metadata | Read |
| Webhooks | Manage |

## Strategy 4: GitLab CI/CD

Use GitLab CI/CD pipelines for the saddle robot on GitLab
instances (self-hosted or GitLab.com).

### GitLab CI Configuration

```yaml
# .gitlab-ci.yml
stages:
  - deploy
  - execute
  - store

deploy-saddle:
  stage: deploy
  script:
    - npm ci --production
    - npm run build
  artifacts:
    paths:
      - dist/
    expire_in: 1 hour

execute-saddle-robot:
  stage: execute
  script:
    - node saddle-robot/index.js
    - cat .saddle/logs/*.json
  artifacts:
    paths:
      - .saddle/logs/
    expire_in: 7 days
  variables:
    SBOT_PLATFORM: gitlab
    SBOT_MEMORY_ENGINE: storage

store-memory-results:
  stage: store
  script:
    - |
      # Upload results to storage backend
      curl -X POST "${SBOT_MEMORY_BUCKET_URL}/upload" \
        -H "Authorization: Bearer ${MEMORY_BUCKET_TOKEN}" \
        -F "file=@.saddle/logs/results.json"
  when: always
```

## Strategy 5: Forgejo Actions

Forgejo supports GitHub-compatible workflows. Use the same
configuration as GitHub Actions with Forgejo-specific adjustments.

### Forgejo Workflow

```yaml
# .forgejo/workflows/saddle.yaml
name: Saddle Robot

on:
  schedule:
    - cron: '*/15 * * * *'
  push:
    branches: [main]

jobs:
  run-saddle:
    runs-on: ubuntu-latest
    steps:
      - uses: forgejo/actions/checkout@v1
      - uses: forgejo/actions/setup-node@v1
        with:
          node-version: '20'
      - run: npm ci --production
      - run: node saddle-robot/index.js
```

## Strategy 7: Docker/VM Self-Hosted

Full containerized deployment for maximum control and resource access.

### Docker Compose

```yaml
# docker-compose.yml
version: '3.8'

services:
  saddle-robot:
    build:
      context: .
      dockerfile: Dockerfile.saddle
    container_name: saddle-robot
    ports:
      - "3000:3000"
    environment:
      - SBOT_PLATFORM=auto
      - SBOT_MEMORY_ENGINE=storage
      - SBOT_MEMORY_BUCKET_URL=${MEMORY_BUCKET_URL}
      - SBOT_API_TOKEN=${SBOT_TOKEN}
      - SBOT_WEBHOOK_SECRET=${WEBHOOK_SECRET}
    volumes:
      - ./saddle-data:/app/data
      - ./saddle-logs:/app/logs
    restart: unless-stopped
    depends_on:
      - saddle-db

  saddle-db:
    image: mysql:8.0
    container_name: saddle-db
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MYSQL_DATABASE: saddle
      MYSQL_USER: saddle_user
      MYSQL_PASSWORD: ${DB_USER_PASSWORD}
    volumes:
      - saddle-db-data:/var/lib/mysql
    ports:
      - "3306:3306"

volumes:
  saddle-db-data:
```

### Dockerfile

```dockerfile
FROM node:20-slim

RUN apt-get update && apt-get install -y \
    chromium \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

COPY package*.json ./
RUN npm ci --production

COPY . .

EXPOSE 3000

HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD curl -f http://localhost:3000/health || exit 1

CMD ["node", "saddle-robot/index.js"]
```

## HTTPS Communication Between Sites

All cross-site communication uses HTTPS with proper certificate
validation. The saddle robot uses HTTPS for:

1. Webhook endpoints between deployed sites
2. API calls to GitHub/GitLab/Forgejo/Gitea
3. Storage bucket communication (HF/Kaggle/ModelScope/Terabox)
4. SCDN asset delivery
5. Internal service mesh communication

### Certificate Management

```typescript
interface SSLOptions {
  cert: string
  key: string
  ca?: string
  rejectUnauthorized: boolean
  minVersion: 'TLSv1.2' | 'TLSv1.3'
}
```

## Decision Matrix

| Strategy | Use Case | Pros | Cons |
|----------|----------|------|------|
| Netlify | Static web + edge functions | Fast, free tier | Limited runtime |
| Vercel | Serverless edge runtime | Global edge | Vendor lock-in |
| GitHub Actions | CI/CD integrated bot | Native GitHub | Time limits |
| GitLab CI | Self-hosted or cloud CI | Full control | Self-hosted needs infra |
| Forgejo | Self-hosted lightweight | Minimal footprint | Smaller ecosystem |
| Gitea | Self-hosted minimal | Very lightweight | Limited integrations |
| Docker/VM | Full control deployment | All resources | Requires infra management |
