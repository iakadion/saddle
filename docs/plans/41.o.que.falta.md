> **Data:** 2026-06-08

## Sumário

`@devthink/webscrape` é um toolkit all-in-one que combina scraping, serialização multi-formato, AI formatting e chunking para RAG — um posicionamento único no mercado. No entanto, 3 gaps críticos impedem a adoção em produção: ausência de anti-detection real, queue persistente e suporte Docker. Este documento lista tudo que falta, priorizado por impacto.

## 2. Correções Críticas (P0)

### 2.1 Anti-Detection / Stealth

**Problema:** Nenhuma proteção real contra bots. O toolkit falha contra Cloudflare, DataDome, PerimeterX.

**Estado atual:**
- `browser.ts:13`: User-Agent único hardcoded como default do `AgentBrowser`
- `browser.ts:37`: `'--disable-web-security'` hardcoded nos launch args (risco de segurança)
- `headers.ts:9-38`: Apenas 4 profiles estáticos (Chrome/FF/Safari × Win/Mac)
- `optionalDependencies` em `package.json:778-781`: `playwright-extra` e `puppeteer-extra-plugin-stealth` estão listados mas **não são importados em nenhum arquivo**

**O que falta:**

| Capacidade | Implementado | Referência do concorrente |
|-----------|-------------|---------------------------|
| Fingerprint randomization | ❌ | Crawlee: fingerprints human-like automáticos |
| TLS fingerprint rotation | ❌ | Browserless: TLS fingerprint rotation |
| Canvas/WebGL spoofing | ❌ | Firecrawl: stealth mode com proxy residential |
| Navigator property randomization | ❌ | Browserless: BrowserQL |
| Captcha solving | ❌ | Firecrawl: captcha handling integrado |
| Proxy residential | ❌ | Firecrawl/Browserless: IP rotation gerenciada |

**Implementação necessária:**
1. Integrar `puppeteer-extra-plugin-stealth` em `browser.ts` — importar e aplicar ao browser launcher
2. Usar `playwright-extra` como wrapper do Playwright em vez de `playwright` direto (já é dependência opcional)
3. Remover `'--disable-web-security'` de `browser.ts:37` ou torná-lo opcional via config
4. Expandir `headers.ts` para 20+ profiles com versões dinâmicas de Chrome/FF
5. Adicionar config de `stealth: boolean` ao `AgentBrowser` (já existe em `browser.ts:21` como `stealth: true` mas não é usado)

**Arquivos afetados:**
- `browser.ts:28-44` — reescrever `launch()` para usar `playwright-extra`
- `browser.ts:11-22` — expandir `DEFAULTS` com opções de stealth
- `headers.ts:9-38` — adicionar profiles dinâmicos

---

### 2.2 Persistent Queue

**Problema:** Crawler usa `Set<string>` in-memory para visited tracking e `Array` como queue. Impossível resumir crawls após crash, impossível lidar com milhões de URLs.

**Estado atual:**
- `crawler.ts:56`: `const visited = new Set<string>();`
- `crawler.ts:57`: `const queue: CrawlEntry[] = [{ url: startUrl, depth: 0 }];`
- `crawler.ts:63`: `while (queue.length > 0 && results.length < maxPages)`
- `crawler.ts:64`: `const batch = queue.splice(0, maxConcurrent);`
- `better-sqlite3` já é dependência em `package.json:237`

**O que falta:**

| Capacidade | Implementado | Referência do concorrente |
|-----------|-------------|---------------------------|
| Queue persistente (sobrevive restarts) | ❌ | Crawlee: `RequestQueue` com SQLite/disk/cloud |
| Dedup persistente | ❌ | Crawlee: URLs processadas sobrevivem a restarts |
| Priorização de requests | ❌ | Crawlee: FIFO/LIFO |
| Auto-skip de URLs processadas | ❌ | Crawlee |

**Implementação necessária:**
1. Criar `queue.ts` com `SqliteQueue` usando `better-sqlite3`
2. Schema SQLite: `CREATE TABLE requests (url TEXT PRIMARY KEY, depth INT, status TEXT, created_at INT, processed_at INT)`
3. Substituir `Set<string>` + `Array` em `crawler.ts` por `SqliteQueue`
4. Adicionar `persist?: boolean | string` ao `CrawlOptions` (path do SQLite)
5. Manter fallback in-memory para uso sem persistência

**Arquivos afetados:**
- Novo: `queue.ts` — classe `SqliteQueue`
- `crawler.ts:39-115` — refatorar `crawl()` para usar queue
- `types.ts` — adicionar `CrawlOptions.persist`

---

### 2.3 Docker Support

**Problema:** Nenhum container de deploy. Impossível rodar em Kubernetes, Railway, Fly.io.

**Estado atual:**
- Nenhum `Dockerfile` no repositório (verificado via glob)
- Nenhum `docker-compose.yml`
- `server.ts:128-134` — `createServer()` retorna Hono fetch handler
- `server.ts:132` — host hardcoded `'0.0.0.0'` (AUDITORIA-DADOS.md)

**O que falta:**
- Todos os 7 concorrentes oferecem Docker (Crawlee templates, Browserless Docker-first, Firecrawl self-hosted)

**Implementação necessária:**
1. Criar `Dockerfile` multi-stage: build → production
2. Criar `docker-compose.yml` com Redis/SQLite como opções
3. Fixar `server.ts:132` — default para `127.0.0.1` (AUDITORIA-DADOS.md)
4. Adicionar docs de deploy: Railway, Fly.io, AWS ECS

**Arquivos afetados:**
- Novo: `Dockerfile`
- Novo: `docker-compose.yml`
- `server.ts:132` — alterar default host

## 3. Gaps Competitivos (P1)

### 3.1 MCP Server

**Problema:** Não pode ser usado por AI agents (Claude Desktop, Cursor, Windsurf) nativamente.

**Estado atual:**
- Zero integração MCP em qualquer arquivo
- `server.ts` fornece REST API mas não MCP

**Concorrentes com MCP:**
- Playwright: `@playwright/mcp` — browser automation para AI agents
- Firecrawl: `firecrawl-mcp` — scrape/crawl como MCP tools
- Browserless: MCP server integrado
- Puppeteer: `chrome-devtools-mcp`

**Implementação necessária:**
1. Criar pacote `@devthink/webscrape-mcp`
2. Expor endpoints como MCP tools: `scrape`, `crawl`, `batch`, `extract`, `serialize`
3. Usar SDK oficial `@modelcontextprotocol/sdk`
4. Adicionar configuração MCP ao `cli.ts`

**Arquivos afetados:**
- Novo: `mcp.ts` ou pacote separado
- `cli.ts` — adicionar subcomando `mcp`

---

### 3.2 Session Persistence

**Problema:** `CookieJar` e `ScrapingSession` são in-memory. Perdem estado entre execuções.

**Estado atual:**
- `session.ts:11-81`: `CookieJar` com `Map<string, Cookie>` in-memory
- `session.ts:83-105`: `ScrapingSession` com `Map<string, unknown>` in-memory
- Sem persistência em disco ou banco

**Concorrentes:**
- Browserless: 90 dias de retenção de cookies/cache/localStorage
- Crawlee: persiste sessões em disco

**Implementação necessária:**
1. Adicionar opção de file-based storage ao `CookieJar`
2. Adicionar opção SQLite para `ScrapingSession`
3. Adicionar `save(path)` / `load(path)` methods
4. Manter in-memory como default para backward compatibility

**Arquivos afetados:**
- `session.ts:11-105` — adicionar persistência

---

### 3.3 Zod Schema Extraction

**Problema:** Não é possível extrair dados estruturados com validação de schema.

**Estado atual:**
- `agent.ts:68-118`: `formatForAgent()` gera output genérico para AI agents
- `tokens.ts:37-44`: `MODEL_PRICES` hardcoded
- `zod` já é dependência (`package.json:421`)

**Concorrentes:**
- Firecrawl: structured output com Zod schemas
- Crawlee: structured output

**Implementação necessária:**
1. Criar `extractWithSchema(url, schema)` — scrape + extrair + validar com Zod
2. Usar LLM para extrair dados baseado no schema quando necessário
3. Gerar output TypeScript tipado
4. Integrar com `server.ts` como novo endpoint `/scrape/schema`

**Arquivos afetados:**
- Novo: `schema-extract.ts`
- `server.ts` — novo endpoint
- `types.ts` — tipos para schema extraction

## 6. Resumo de Impacto

| Capacidade | Antes | Depois |
|-----------|-------|--------|
| Anti-detection | ❌ User-Agent fixo | ✅ Stealth plugin + fingerprint rotation |
| Queue | ❌ In-memory, sem persistência | ✅ SQLite, sobrevive restarts |
| Docker | ❌ Nenhum | ✅ Dockerfile multi-stage |
| MCP | ❌ Nenhum | ✅ Server MCP para AI agents |
| Sessions | ❌ In-memory | ✅ Persistente (SQLite/file) |
| Schema extraction | ❌ Nenhum | ✅ Zod validation |
| PDF | ❌ Screenshots apenas | ✅ Geração de PDF |
| Deploy | ❌ Manual | ✅ Docker + docs Railway/Fly.io |

### Posicionamento Atualizado

```
                    Mais Abstrato
                         ↑
                         │
           Firecrawl ────┼──── Browserless
           (API-first)   │    (DaaS)
                         │
     ←───────────────────┼──────────────────→
   Mais simples          │          Mais complexo
                         │
          webscrape ─────┼──── Crawlee
          (Toolkit+)     │    (Framework)
                         │
                         ↓
                    Menos Abstrato
```

**Depois do roadmap:** webscrape sobe para "Toolkit+" — mantendo o diferencial AI/RAG e ganhando production readiness.
