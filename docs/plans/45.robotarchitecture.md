# Saddle Robot Architecture

> Super bot: agent browser, scraper, captcha bypass, GitHub/GitLab/Forgejo/Gitea automation.
> Transform storage memory into computational memory for unlimited processing.

## Overview

Saddle is a self-hosted AI agent platform that combines browser automation,
scraping, captcha bypass, and multi-platform bot functionality into a single
runtime. It operates as a virtual machine agent that can deploy to multiple
platforms and store unlimited memory in remote repositories.

## Core Components

### 1. Agent Browser Engine

The browser agent captures user interactions (mouse movement, clicks, scrolling)
and replays them. It uses Brave browser via Playwright with the real user
profile for persistence.

#### Movement Capture

```
Browser → Movement Capture → JSON Log → Storage → Replay
```

Supports:
- Virtual mouse movement (arrow trails)
- Click coordinates
- Scroll events
- Keyboard input
- Screenshot capture
- Session recording

#### Captcha Bypass

Saddle handles three captcha types:

| Type | Method | Success Rate |
|------|--------|-------------|
| hCaptcha | Cloudflare Turnstile proxy | High |
| Cloudflare Turnstile | Managed challenge solving | Medium-High |
| reCAPTCHA | Token rotation + headless solve | Medium |

### 2. Multi-Platform Bot Engine

The bot engine operates across platforms through a unified interface:

```typescript
interface PlatformAdapter {
  name: string
  type: 'github' | 'gitlab' | 'forgejo' | 'gitea' | 'discord'
  authenticate(token: string): Promise<boolean>
  listRepos(): Promise<Repo[]>
  createWebhook(payload: WebhookPayload): Promise<void>
  executeBot(commands: BotCommand[]): Promise<BotResult>
}
```

Platforms supported:
- **GitHub** - Actions, webhooks, PR automation, issue triage
- **GitLab** - CI/CD pipelines, merge requests, webhooks
- **Forgejo** - Self-hosted Git, lightweight alternative
- **Gitea** - Self-hosted Git service, minimal footprint
- **Discord** - Bot commands, webhook reactions, automated responses

### 3. Computational Memory System

This is the core innovation of saddle. It transforms storage memory into
computational memory through a memory engine.

#### Memory Layers

| Layer | Type | Source | Capacity |
|-------|------|--------|----------|
| L1 | RAM | System memory | Limited (ephemeral) |
| L2 | GPU VRAM | Graphics memory | Limited (compute-bound) |
| L3 | Storage RAM | Repository storage | Effectively unlimited |
| L4 | External Buckets | HF/Kaggle/ModelScope/Terabox | Unlimited |

#### Storage-to-Compute Transformation

```
Repository Storage (L3)
    → Memory Engine reads blobs
    → Transforms into virtual RAM
    → Processed as computational memory
    → Results written back to storage
```

The memory engine acts as a bridge between storage objects (files, blobs,
assets) and computational processing. It can load file contents into
memory, process them, and persist results back to storage.

#### Memory Engine API

```typescript
interface MemoryEngine {
  loadFromStorage(repo: string, path: string): Promise<MemoryObject>
  process(operation: ComputeOperation): Promise<MemoryResult>
  persist(result: MemoryResult, target: StorageTarget): Promise<void>
  release(memoryId: string): Promise<void>
}
```

## Deploy Strategies

### Strategy 1: HTTPS Communication Between Sites

Two or more deployed sites communicate via HTTPS. The saddle robot
receives commands from a web interface and executes actions.

```
Site A (web interface) ──HTTPS──▶ Site B (saddle robot backend)
                                      │
                                      ├──▶ GitHub API
                                      ├──▶ GitLab API
                                      ├──▶ Browser Engine
                                      └──▶ Storage Backends
```

### Strategy 2: GitHub/GitLab/Forge Pipelines

Use CI/CD pipelines (GitHub Actions, GitLab CI, Forgejo Actions) to
deploy and run the saddle robot as a scheduled or triggered job.

### Strategy 3: Docker/VM Deployment

Package saddle as a Docker container or VM image for self-hosted
deployment with full resource access.

```dockerfile
FROM node:20-slim
WORKDIR /app
COPY package*.json ./
RUN npm ci --production
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
```

## NPM Package Publishing

Saddle can be published as an NPM package `@wenathlan/saddle` for
distribution as both a library and a CLI tool.

### Package Structure

```
@wenathlan/saddle/
├── lib/
│   ├── browser.js        (agent browser engine)
│   ├── bot.js            (multi-platform bot engine)
│   ├── captcha.js        (captcha bypass module)
│   ├── memory-engine.js  (storage-to-compute transformation)
│   └── deploy.js         (deploy strategy implementations)
├── bin/
│   └── saddle.js         (CLI entry point)
├── docs/
│   └── index.md          (package documentation)
├── package.json
└── README.md
```

### As Library vs Binary

| Mode | Entry Point | Usage |
|------|------------|-------|
| Library | `require('@wenathlan/saddle')` | Import as Node module |
| CLI | `saddle --command capture` | Run as terminal command |
| Binary | `node_modules/.bin/saddle` | Direct execution |

## SCDN Integration

Saddle supports integration with Static Content Delivery Networks for
hosting browser assets, capture files, and deployment payloads.

The SCDN pipeline:
1. Captures browser session data
2. Uploads assets to SCDN
3. References SCDN URLs in bot results
4. Serves static content from edge locations
