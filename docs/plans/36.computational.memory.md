# Saddle Computational Memory System

> Transform storage memory into computational memory (RAM, GPU).
> Unlimited memory through repository buckets and external storage.

## Overview

The saddle robot implements a unique computational memory
architecture that transforms storage memory (files, blobs,
assets in repositories) into computational memory (RAM, GPU
VRAM) for processing. This enables effectively unlimited
memory for AI agent operations.

## Memory Architecture

### Layer Diagram

```
┌─────────────────────────────────────────────────────┐
│                 Computation Layer                      │
│                   (RAM / GPU)                        │
│                                                      │
│    Processing   │   Inference   │   Cache            │
│                  │   (ML Models)  │                   │
├─────────────────────────────────────────────────────┤
│              Memory Engine (Bridge)                  │
│                                                      │
│    Load  │  Transform  │  Process  │  Persist       │
├─────────────────────────────────────────────────────┤
│                Storage Layer                        │
│                                                      │
│    Repositories │  HF Buckets │  Kaggle │  S3      │
└─────────────────────────────────────────────────────┘
```

### Memory Transformation Flow

```
1. Storage Object (file/blob in repo)
       │
       ▼
2. Memory Engine loads object
       │
       ▼
3. Object parsed into memory buffer
       │
       ▼
4. Memory buffer mapped to virtual RAM
       │
       ▼
5. Computation performed on virtual RAM
       │
       ▼
6. Results written back to storage
       │
       ▼
7. Storage object updated
```

## Memory Engine Implementation

### Core Class

```typescript
class MemoryEngine {
  private storage: Map<string, MemoryObject>
  private backends: StorageBackend[]

  constructor(config: MemoryEngineConfig) {
    this.backends = config.backends.map(
      (backend) => StorageBackendFactory.create(backend)
    )
  }

  async load(key: string): Promise<MemoryObject | null> {
    try {
      for (const backend of this.backends) {
        const object = await backend.load(key)
        if (object !== null) {
          return this.transformToCompute(object)
        }
      }
      return null
    } catch (error) {
      throw new Error(
        `MemoryEngine.load failed for key "${key}": ${error.message}`
      )
    }
  }

  async persist(
    key: string,
    data: ComputeResult
  ): Promise<boolean> {
    try {
      const storageObject = this.transformToStorage(data)
      for (const backend of this.backends) {
        await backend.save(key, storageObject)
      }
      return true
    } catch (error) {
      throw new Error(
        `MemoryEngine.persist failed for key "${key}": ${error.message}`
      )
    }
  }

  private transformToCompute(
    object: StorageObject
  ): MemoryObject {
    const buffer = Buffer.from(object.data)

    return {
      id: object.key,
      buffer: buffer,
      size: buffer.byteLength,
      type: object.mimeType,
      createdAt: new Date(),
    }
  }

  private transformToStorage(
    result: ComputeResult
  ): StorageObject {
    return {
      key: result.id,
      data: result.payload,
      mimeType: result.mimeType ?? 'application/octet-stream',
      metadata: result.metadata,
    }
  }

  release(key: string): Promise<void> {
    this.storage.delete(key)
    return Promise.resolve()
  }
}
```

## Computational Memory Use Cases

### Use Case 1: Large File Processing

Load a large file from repository storage into virtual RAM,
process it, and write results back.

```
repo://my-repo/large-file.bin
    → Memory Engine loads into buffer (virtual RAM)
    → Processing pipeline transforms buffer
    → Results written back to repo
```

### Use Case 2: ML Model Inference

Store ML model weights in repository storage, load into
GPU VRAM for inference, persist results.

```
repo://models/my-model/weights.bin
    → Memory Engine loads into GPU buffer
    → Inference engine processes
    → Results stored as repo artifacts
```

### Use Case 3: Browser Session Memory

Capture browser sessions as JSON, store in repo, replay
on another machine with full session memory.

```
repo://saddle/sessions/session-001.json
    → Memory Engine loads session log
    → Browser engine replays movements
    → Execution results stored back
```

## Performance Characteristics

| Aspect | Metric | Notes |
|--------|--------|-------|
| Load latency | Depends on storage backend | Local storage fastest |
| Process throughput | Depends on compute layer | RAM fastest, storage limited |
| Persist latency | Depends on storage backend | Batch writes preferred |
| Memory overhead | ~2x storage size | Buffer + metadata |
| Max capacity | Effectively unlimited | Bounded by storage targets |

## Error Handling

The memory engine implements try-catch around all storage
operations with contextual error logging for later tracing.

```typescript
async safeLoad<T>(
  key: string
): Promise<{ success: boolean; data?: T; error?: string }> {
  try {
    const result = await this.load(key)
    return { success: true, data: result as T }
  } catch (error) {
    return {
      success: false,
      error: error instanceof Error ? error.message : 'Unknown error',
    }
  }
}
```

## Storage Backend Factory

```typescript
class StorageBackendFactory {
  static create(config: StorageConfig): StorageBackend {
    switch (config.type) {
      case 'github':
        return new GitHubStorageBackend(config)
      case 'gitlab':
        return new GitLabStorageBackend(config)
      case 'forgejo':
        return new ForgejoStorageBackend(config)
      case 'gitea':
        return new GiteaStorageBackend(config)
      case 'huggingface':
        return new HFStorageBackend(config)
      case 'kaggle':
        return new KaggleStorageBackend(config)
      case 'modelscope':
        return new ModelScopeStorageBackend(config)
      case 'filehosting':
        return new FileHostingStorageBackend(config)
      default:
        throw new Error(
          `Unknown storage type "${config.type}"`
        )
    }
  }
}
```
